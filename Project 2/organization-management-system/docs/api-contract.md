# OrgSphere API Contract & Specification

## 1. REST Standards & Conventions
- **Base URL Prefix**: `/api/v1`
- **Content Type**: `application/json` for all requests and responses.
- **Correlation ID**: All requests accept an optional `X-Request-Id` header (UUID). If missing, one is generated by the server and returned in response headers and envelopes.
- **Timestamps**: ISO 8601 format (`YYYY-MM-DDTHH:mm:ss.sssZ`).

---

## 2. Standardized Response Envelopes

### Success Envelope
```json
{
  "success": true,
  "data": { ... } | [ ... ],
  "meta": {
    "page": 1,
    "limit": 20,
    "total": 100,
    "totalPages": 5,
    "hasNextPage": true,
    "hasPreviousPage": false
  }
}
```
*(The `meta` block is present for paginated list endpoints and omitted for single-resource responses).*

### Error Envelope
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The provided request body failed validation constraints.",
    "details": [
      {
        "field": "email",
        "message": "Invalid email address format."
      }
    ],
    "requestId": "a53e6b12-8924-4f01-9a78-b9841fbc8102"
  }
}
```
*Note: Internal error stack traces are returned only when `NODE_ENV === 'development'`.*

## 3. Standard HTTP Status Codes

| Code | Meaning | When Used |
|---|---|---|
| **200 OK** | Success | Standard successful GET, PATCH, PUT, or DELETE. |
| **201 Created** | Created | Resource successfully created (POST). |
| **400 Bad Request** | Validation Failure | Zod schema validation errors, malformed payloads. |
| **401 Unauthorized** | Unauthenticated | Missing, expired, or invalid JWT access token. |
| **403 Forbidden** | Access Denied | Authenticated user lacks required role/permission in the organization. |
| **404 Not Found** | Not Found | Resource does not exist or belongs to another organization (non-enumeration). |
| **409 Conflict** | Conflict | Unique constraint violation (e.g. email or slug already taken). |
| **429 Too Many Requests** | Rate Limited | Exceeded endpoint rate limit (e.g. auth brute-force protection). |
| **500 Internal Error** | Server Error | Unhandled exceptions (sanitized client message returned). |
| **503 Service Unavailable** | Readiness Failure | Essential service (e.g. PostgreSQL) unreachable during `/ready`. |

## 4. Phase 1 Foundation Endpoints

### 1. System Liveness
- **Method / Path**: `GET /api/v1/health`
- **Authentication**: None
- **Response (200 OK)**:
```json
{
  "success": true,
  "data": {
    "status": "ok",
    "timestamp": "2026-09-27T15:00:00.000Z",
    "uptime": 128.45
  }
}
```

### 2. Readiness Probe & Dependency Policy
- **Method / Path**: `GET /api/v1/ready`
- **Authentication**: None
- **Dependency Policy**:
  - **PostgreSQL**: **Hard Dependency**. If database connection fails, the probe returns `503 Service Unavailable`.
  - **Redis**: **Optional Cache Layer in Phase 1**. If Redis is unconfigured or unreachable, the probe returns `200 OK` with Redis status noted as `"unavailable"` or `"disabled"`, ensuring the API continues to operate gracefully.
- **Response (200 OK - All Operational)**:
```json
{
  "success": true,
  "data": {
    "status": "ready",
    "checks": {
      "database": "healthy",
      "redis": "healthy"
    }
  }
}
```
- **Response (200 OK - Redis Offline Fallback)**:
```json
{
  "success": true,
  "data": {
    "status": "ready",
    "checks": {
      "database": "healthy",
      "redis": "unavailable"
    }
  }
}
```
- **Response (503 Service Unavailable - Database Down)**:
```json
{
  "success": false,
  "error": {
    "code": "DATABASE_UNAVAILABLE",
    "message": "PostgreSQL database connection is currently unavailable.",
    "requestId": "..."
  }
}
```

### 3. API Version
- **Method / Path**: `GET /api/v1/version`
- **Authentication**: None
- **Response (200 OK)**:
```json
{
  "success": true,
  "data": {
    "service": "orgsphere-api",
    "version": "1.0.0",
    "environment": "development"
  }
}
```

### 4. Interactive Documentation
- **Method / Path**: `GET /api/v1/docs`
- **Description**: Interactive Swagger UI serving the complete OpenAPI 3.0 specification.
- **Raw Spec**: `GET /api/v1/docs/openapi.json`
